# Updates de la actividad agent skills

## Que se cambio

- Se ajusto el documento al contexto real definido para el repo: una consultora multinacional de software con participantes tecnicos y no tecnicos, alcance local o regional y nivel introductorio de experiencia previa con IA.
- Se reformulo la consigna para que no presuponga que toda tarea debe convertirse en una skill: ahora tambien se admite una recomendacion fundada de no proceduralizar.
- Se agrego un diagnostico contextual inicial para obligar a precisar usuarios, restricciones, datos, riesgos y condiciones reales de implementacion.
- Se incorporo el analisis de al menos un caso fallido o riesgoso durante la prueba.
- Se reforzaron los controles humanos, los escenarios de no uso y la pregunta por los saberes tacitos que pueden perderse al convertir una practica en skill.
- Se volvieron mas observables los criterios de evaluacion.
- Se agrego una instancia sugerida de seguimiento dos semanas despues para observar transferencia real.

## Por que se cambio

- El archivo de contexto del repo pedia una propuesta mas situada para empleados con roles muy diversos, no solo perfiles tecnicos.
- La auditoria pedagogica marco como puntos de mejora la contextualizacion, la agencia de participantes, el trabajo con fallas y la necesidad de no naturalizar la skill como solucion universal.
- Tambien senalo que la evaluacion estaba bien orientada pero todavia poco operacionalizada, por eso se sumaron indicadores observables.

## Efecto esperado

- Una actividad mas adecuada para grupos mixtos.
- Mejor balance entre entusiasmo por la IA y criterio profesional.
- Mayor capacidad para distinguir cuando una skill agrega valor y cuando conviene preservar mas deliberacion humana.
